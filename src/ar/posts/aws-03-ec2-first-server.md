بعد ما أمّنا الحساب في [الجزء الثاني](/posts/aws-02-iam/)، جا وقت أشهر خدمة في AWS. **EC2** (اختصار Elastic Compute Cloud) تعطيك سيرفرات افتراضية تشغّلها خلال دقائق، تدفع عليها وهي شغالة، وتحذفها لما تخلص.

في هذا الجزء بنفهم القرارات اللي تاخذها لما تشغّل سيرفر، وبنشغّل سيرفر ويب يجهّز نفسه تلقائياً، ونوصله بخدمات AWS بدور IAM بدل المفاتيح.

## وش تختار لما تشغّل سيرفر؟

كل سيرفر (يسمونه **Instance**) يتكوّن من قرارات محددة:

| القرار | وش يعني | مثال |
| --- | --- | --- |
| **AMI** | صورة النظام اللي يقلع منها السيرفر | Amazon Linux أو Ubuntu أو Windows |
| **نوع السيرفر** | المعالج والذاكرة وسرعة الشبكة | `t3.micro` |
| **زوج المفاتيح** | طريقة الدخول الآمن عبر SSH | ملف `.pem` عندك |
| **الشبكة** | وين يعيش، وهل له عنوان عام | شبكة افتراضية ومنطقة توفر |
| **مجموعة الأمان** | جدار ناري يحدد مين يوصل له | السماح بالمنفذ 80 |
| **التخزين** | القرص الموصول فيه | قرص EBS بحجم 8 جيجا |
| **User Data** | سكربت يتنفذ أول ما يقلع | تثبيت خادم ويب |

## أنواع السيرفرات

اسم النوع يوصف السيرفر بالكامل. خذ مثلاً `m7g.2xlarge`:

- **`m`:** العائلة، وتحدد الغرض من السيرفر.
- **`7`:** الجيل. الأجيال الأحدث عادة أسرع وأرخص لنفس الأداء.
- **`g`:** ميزة إضافية، وهنا معناها معالج AWS Graviton (بنية ARM).
- **`2xlarge`:** الحجم داخل العائلة.

والعائلات الأساسية:

| العائلة | تناسب | أمثلة |
| --- | --- | --- |
| **عامة** (`t`, `m`) | مواقع الويب وأغلب التطبيقات، توازن بين كل شي | `t3`, `m7i` |
| **محسّنة للمعالجة** (`c`) | المهام الحسابية، ترميز الفيديو، خوادم الألعاب | `c7i` |
| **محسّنة للذاكرة** (`r`, `x`) | قواعد البيانات والكاش في الذاكرة | `r7i` |
| **محسّنة للتخزين** (`i`, `d`) | قراءة وكتابة سريعة جداً على قرص محلي | `i4i` |
| **مسرّعة** (`p`, `g`) | الذكاء الاصطناعي والرسوميات بمعالجات GPU | `g5` |

ابدأ صغير دايماً، وكبّر لما تشوف أرقام تقول إنك تحتاج. وعائلة `t` فيها نظام "رصيد" للمعالج: تشتغل بأداء أساسي وتقدر تتجاوزه لفترات قصيرة، وهذا ممتاز للمشاريع الصغيرة ومو مناسب لحمل ثقيل ومستمر.

## مجموعات الأمان: جدار السيرفر الناري

**مجموعة الأمان** (Security Group) جدار ناري افتراضي يحيط بالسيرفر، وأهم شي تعرفه عنها:

- القواعد فيها **سماح فقط**. ما تكتب "امنع"، أي شي ما سمحت له ممنوع.
- افتراضياً: كل الداخل ممنوع، وكل الخارج مسموح.
- **تتذكر الاتصال** (Stateful): لو سمحت لطلب يدخل، رده يطلع تلقائياً بدون قاعدة خروج.
- تقدر تسمح لعنوان IP، أو **لمجموعة أمان ثانية**. مثلاً: قاعدة البيانات تقبل فقط من مجموعة أمان سيرفرات التطبيق، حتى لو تغيّرت عناوينها.

المنافذ اللي بتقابلها كثير:

| المنفذ | الخدمة |
| --- | --- |
| 22 | SSH: الدخول على سيرفر لينكس |
| 80 | HTTP: مواقع بدون تشفير |
| 443 | HTTPS: مواقع مشفّرة |
| 3389 | RDP: الدخول على سيرفر ويندوز |

::: warning لا تفتح SSH للعالم
لا تخلي المنفذ 22 مفتوح على `0.0.0.0/0`. حدده لعنوانك أنت فقط. والأفضل كمان تستخدم **Session Manager** أو **EC2 Instance Connect** بدل ما تدير مفاتيح بنفسك.
:::

::: tip تشخيص سريع للاتصال
إذا طلع لك **Timeout**، فالطلب ما وصل أصلاً: غالباً مجموعة الأمان. وإذا طلع **Connection refused**، فالطلب وصل للسيرفر لكن ما فيه برنامج يستقبل على هذا المنفذ. هذا الفرق يوفّر عليك وقت كثير.
:::

## User Data: سيرفر يجهّز نفسه

**User Data** سكربت تعطيه للسيرفر وقت التشغيل، ويتنفذ **مرة وحدة** أول ما يقلع وبصلاحيات الجذر. بدل ما تدخل وتثبّت كل شي بيدك، السيرفر يقوم جاهز. وهذا أساس التوسّع التلقائي اللي بنوصله لاحقاً.

## عملي: شغّل سيرفر ويب

الحين بنشغّل سيرفر Amazon Linux يقوم وخادم الويب شغّال عليه.

1. افتح خدمة **EC2** واضغط **Launch instance**، وسمّه `web-1`.
2. اختر صورة **Amazon Linux 2023** ونوع `t3.micro` (أو النوع المتاح في الاستخدام المجاني عندك).
3. أنشئ **زوج مفاتيح** ونزّله، إلا إذا بتدخل من المتصفح بـ EC2 Instance Connect.
4. في **Network settings** اسمح بـ HTTP من أي مكان، وSSH من عنوانك فقط (**My IP**).
5. في **Advanced details**، الصق هذا في خانة **User data**:

   ```bash
   #!/bin/bash
   dnf install -y nginx
   echo "<h1>Hello from $(hostname)</h1>" > /usr/share/nginx/html/index.html
   systemctl enable --now nginx
   ```

6. اضغط **Launch instance**، وانتظر لين تصير الحالة **Running**.

بعد دقيقة أو دقيقتين، انسخ **Public IPv4 address** وافتحه في المتصفح بـ `http://` (مو `https`). لازم تشوف الصفحة واسم السيرفر. ولو حبيت تدخل عليه:

```bash
# صلاحيات الملف لازم تكون مقيدة، وإلا يرفض SSH المفتاح
chmod 400 ~/keys/my-key.pem

# المستخدم الافتراضي في Amazon Linux هو ec2-user
ssh -i ~/keys/my-key.pem ec2-user@عنوان_السيرفر
```

وإذا تبي شرح تفصيلي لخطوات الواجهة بالصور، راجع [كيف تنشئ سيرفر على AWS](/posts/aws/).

## عملي: أعطِ السيرفر دور IAM

في الجزء الثاني قلنا: للخدمات داخل AWS، استخدم دور مو مفاتيح. نطبّقها الحين.

1. من **IAM** افتح **Roles** ثم **Create role**. اختر **AWS service** ثم **EC2**.
2. اربط السياسة الجاهزة `AmazonS3ReadOnlyAccess`، وسمّ الدور `web-s3-read`.
3. ارجع لـ EC2، اختر السيرفر، ثم **Actions** ثم **Security** ثم **Modify IAM role**، واختر الدور.

الحين داخل السيرفر، بدون ما تسوي `aws configure` وبدون أي مفتاح:

```bash
# يعرض هوية مؤقتة من نوع assumed-role، مو مستخدم
aws sts get-caller-identity

# يشتغل لأن الدور يسمح بقراءة S3
aws s3 ls

# يُرفض لأن الدور ما يسمح بهذا: أقل صلاحية على أرض الواقع
aws ec2 describe-instances --region eu-central-1
```

الأمر الأخير يرجع لك خطأ `UnauthorizedOperation`، وهذا هو المطلوب بالضبط: السيرفر يقدر يسوي اللي عطيته فقط.

## الإيقاف أو الحذف؟

| الحالة | السيرفر | القرص | تدفع على |
| --- | --- | --- | --- |
| **Running** | شغّال | موجود | المعالجة والتخزين |
| **Stopped** | موقف | موجود وبياناتك فيه | التخزين فقط |
| **Terminated** | محذوف نهائياً | يُحذف قرص النظام افتراضياً | لا شي |

ولاحظ إن عنوان IP العام **يتغيّر** كل ما توقف السيرفر وتشغّله. بنشوف الحل في الجزء الجاي.

::: security نظّف بعد التجربة
لما تخلص، اختر السيرفر ثم **Instance state** ثم **Terminate instance**. السيرفر المنسي هو أشهر سبب لفاتورة ما توقعتها.
:::

## الخلاصة

- السيرفر مكوّن من: صورة نظام (AMI)، ونوع، ومفاتيح، وشبكة، ومجموعة أمان، وتخزين، وUser Data.
- اسم النوع يقول كل شي: العائلة والجيل والحجم. ابدأ صغير وكبّر حسب الأرقام.
- مجموعات الأمان سماح فقط، وتتذكر الاتصال، وتقدر تشير لمجموعات ثانية.
- **Timeout** يعني مجموعة الأمان غالباً، و**Connection refused** يعني التطبيق.
- User Data يجهّز السيرفر تلقائياً، والدور يعطيه صلاحيات بدون مفاتيح.
